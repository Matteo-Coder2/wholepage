# Incident kit — prepared BEFORE first submission

Why this exists: GoFullPage (11M users) was removed with zero warning over one
peripheral design asset, was still down 3+ days later WITH counsel and a
registered trademark, and CWS appeals have been **one-shot** since 2025. The
first appeal must be the complete one; nothing here can be written well under
panic.

## 1. Status post template (publish within 1 hour of any takedown)

> WholePage is temporarily unavailable in the Chrome Web Store while we resolve a
> policy/IP dispute with the store. **This is not a security issue** — WholePage
> runs entirely on your device, makes zero network requests, and its full source
> is public at [repo]. If Chrome disabled the extension in your browser, you can
> re-enable it at chrome://extensions. WholePage remains available on
> [Edge Add-ons link]. Updates here as we have them.

Channels, in order: repo README banner + pinned issue, the listing's support
site page, X account.

## 2. Appeal skeleton (CWS One Stop Support)

- Extension ID, version, exact removal notice text + date
- One paragraph: what the extension does, single purpose, permission list with
  justifications (copy from docs/store-listing.md)
- Link to the public repo + statement that the shipped package is diffable
  against it
- Link to the **pre-recorded screencast** demonstrating full functionality
  (record at each release; the only documented 24h reinstatement came from a
  detailed appeal with screencast)
- Asset provenance: link docs/asset-provenance.md — every visual asset is
  original, generated by scripts in this repo, no third-party artwork
- Requested action + contact

## 3. If the notice is copyright/DMCA

- File the CWS appeal AND a DMCA counter-notice the SAME DAY, in parallel.
- Counter-notice needs: identification of the removed material, a good-faith
  statement under penalty of perjury, consent to US jurisdiction, physical
  signature and address. Decide the filing entity BEFORE an incident
  (individual vs. LLC — an existing LLC is available; confirm which entity owns
  the extension at launch).
- Preserve everything: the notice, the listing state (chrome-stats snapshot),
  Wayback captures.

## 4. Verification drills (quarterly)

- Publisher email: dedicated, monitored, passkey 2FA, no forwarding. Test login.
- chrome-stats (or similar) monitoring on our own listing ID — learn of a
  takedown from data, not from users.
- Confirm the Edge listing still mirrors the current version.
- Re-read: real notices appear ONLY in the Developer Dashboard; emailed
  "violations" with links are phishing (the campaign that converted 16
  extensions, including two full-page screenshot tools, into malware).
